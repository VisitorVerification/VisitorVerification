# 방문자 확인 시스템 — Arduino UNO 모형 문

## 1. 파일과 실행 위치

`door_controller/door_controller.ino`를 Arduino IDE에서 엽니다.
스케치 폴더 이름과 ino 파일 이름은 모두 `door_controller`로 유지하세요.
이 코드는 Python이 아니라 Arduino 보드에서 실행되는 C++ 코드입니다.
Arduino UNO R3/ATmega328P를 기준으로 작성했습니다. UNO R4용 설정은 사용하지 않습니다.
현재 구성은 **통과 센서 없이 서보모터와 3색 LED만 사용**합니다.

## 2. 배선

전원을 연결하기 전에 아래 핀과 실제 모듈 표시를 확인하세요.

| Arduino 핀 | 연결 |
|---|---|
| D9 | 서보 신호선 |
| D4 | 빨강 LED 입력 |
| D5 | 노랑 LED 입력 |
| D6 | 초록 LED 입력 |
| GND | LED 모듈의 GND. VCC 핀이 있는 모듈은 제품 사양대로 추가 연결 |
| USB | 노트북과 연결. Arduino 전원과 시리얼 통신 |

D2는 사용하지 않으며, 통과 센서는 연결하지 않습니다.

서보 전원은 **외부 5V 전원**에서 공급하고 외부 전원 GND를 Arduino GND와 공통 연결합니다.
서보 전원선을 UNO 5V 핀에 연결하지 않습니다. 외부 5V의 +를 UNO VIN에 넣지도 않습니다.
LED 핀별 색 배정과 HIGH/LOW 활성 방식은 실제 모듈에 맞춰 코드 상단에서 변경할 수 있습니다.
LED 모듈이 아닌 개별 LED를 쓰면 전류 제한 저항이 필요합니다.

## 3. 동작

| 상태 | LED | 동작 |
|---|---|---|
| 대기 | 꺼짐 | 문 닫힘 |
| OPEN | 초록 | 기본 0도 → 90도로 서서히 열림 |
| 열림 유지 | 초록 | 열림 완료 처리(OPENED) 후 30초가 되면 닫기 시작 |
| 닫힘 | 꺼짐 | 닫힘 목표 각도 도달 + 여유 시간 후 CLOSED 전송 |
| DENY | 빨강 | 닫힘 유지. 5초 뒤 대기로 복귀 |
| WAIT | 노랑 고정 | 선택 기능 F7의 승인 대기. OPEN/DENY/IDLE로 변경 |
| RETRY | 노랑 깜빡임 | 인식 재시도 안내. 이후 상태는 PC가 결정 |
| HINT | 노랑 깜빡임 | 공통 명세의 인식 재시도 명령. RETRY와 같은 동작 |

- 모든 대기는 `millis()`의 시간 차이로 처리하며 `delay()`를 사용하지 않습니다.
- 서보는 기본 20ms마다 1도씩 이동하고 목표 각도 명령 후 250ms 여유 시간을 둡니다.
  90도 이동은 약 2초입니다. 실제 움직임은 서보와 모형 하중에 따라 달라집니다.
- 통과 감지와 통과 후 3초 닫힘은 제거했습니다. 사람이 지나갔는지와 관계없이 정해진 시간 뒤 닫습니다.
- 코드 상단의 `OPEN_HOLD_MS = 30000UL`이 열림 유지 시간입니다.
  예를 들어 5초로 바꾸려면 `5000UL`로 수정하고 다시 업로드합니다.
- 30초는 OPEN 명령 수신 시점이 아니라 OPENED가 출력되는 시점부터 계산합니다.
  OPEN부터 CLOSED까지는 여기에 열고 닫는 시간(각 약 2초)이 더해집니다.
- **열린 동안 OPEN을 다시 받으면 그 수신 시점부터 30초를 다시 잽니다.**
  예: OPENED 후 20초에 OPEN을 받으면 원래의 30초가 아니라 약 50초 시점에 닫기 시작합니다.
  열리는 중에 받은 OPEN은 움직임을 유지하고, 열림 완료 후 30초를 잽니다.
- 닫히는 중 새 OPEN을 받으면 현재 각도에서 다시 열고, 열림 완료 후 30초를 유지합니다.
  시작 시 초기 닫힘 처리 중에는 READY가 될 때까지 OPEN을 BUSY로 거부합니다.
- 열림·닫힘 주기가 진행되는 중의 DENY/WAIT/IDLE/HINT/RETRY는 BUSY로 거부합니다.
  다른 표시 명령으로 출입 허용 주기를 중간에 끊지 않습니다.
- IDLE은 표시 초기화용입니다. 열린 문을 즉시 강제로 닫는 명령으로 사용하지 않습니다.

## 4. 시리얼 프로토콜

9600bps / 8N1 / 대문자 ASCII / 줄바꿈 단위입니다. LF, CRLF, CR을 지원합니다.
예: Python에서 `serial_port.write(b"OPEN\n")`.

### PC → Arduino

| 명령 | 의미 |
|---|---|
| OPEN | 출입 허용. 문 열기 |
| DENY | 거절. 빨강 LED 5초 |
| IDLE | 대기 표시 |
| WAIT | 선택 기능 승인 대기. 노랑 고정 |
| RETRY | 인식 불가/재시도. 노랑 깜빡임 |
| HINT | 공통 명세의 인식 재시도 표시. RETRY와 같은 동작 |

PC는 공통 명세의 HINT를 사용하면 됩니다. 이전 RETRY도 호환용으로 허용합니다.
인식 불가 5초 후 미등록 처리하는 판단은 A/B의 PC 프로그램에서 수행합니다.

### Arduino → PC

| 응답 | 의미 |
|---|---|
| CLOSED | 닫힘 목표 각도 명령과 여유 시간 완료. 시작 시에도 한 번 전송 |
| READY | 시작 시 닫힘 처리 후 명령 수신 준비 완료 |
| OPENED | 열림 목표 각도 명령과 여유 시간 완료 |
| BUSY | 현재 문 동작 주기 중이라 해당 명령을 적용하지 않음 |
| ERROR UNKNOWN_COMMAND | 지원하지 않는 명령. 문 상태 유지 |
| ERROR LINE_TOO_LONG | 23자를 넘는 줄을 전체 무시 |
| ERROR INVALID_CHARACTER | ASCII 명령에 허용되지 않는 문자. 줄 전체 무시 |
| ERROR TIMEOUT | 줄바꿈 없이 부분 명령이 1초 이상 중단됨 |

TIMEOUT 후에는 다음 줄바꿈까지 무시합니다. 다시 보내기 전에 먼저 줄바꿈으로 복구하세요.
통과 센서를 제거했으므로 PASS는 전송하지 않습니다. PC는 PASS를 기다리지 않아야 합니다.
OPENED와 CLOSED는 위치 센서 확인이 아닌 **소프트웨어의 목표 각도 처리 완료**입니다.
기구 걸림, 서보 단선, 실제 문 위치는 이 코드로 확인할 수 없습니다.

## 5. Arduino IDE 업로드

1. Arduino IDE에서 `door_controller/door_controller.ino`를 엽니다.
2. 보드 매니저에서 Arduino AVR Boards를 설치하고 보드를 **Arduino Uno**로 선택합니다.
3. USB 연결 후 실제 보드의 COM 포트를 선택합니다.
4. `Servo.h`를 찾지 못하면 라이브러리 매니저에서 **Servo (Arduino)**를 설치합니다.
5. 검증(체크 표시) 후 업로드(화살표)를 누릅니다.
6. 시리얼 모니터를 **9600 baud**, 줄 끝은 **Newline** 또는 **Both NL & CR**로 설정합니다.
7. 보드가 재시작하면 CLOSED, READY가 보입니다. 이미 출력이 지나갔다면 리셋 버튼으로 확인합니다.

Python과 Arduino IDE 시리얼 모니터가 같은 COM 포트를 동시에 열 수 없습니다.
Python 연동 전에 시리얼 모니터를 닫고, 포트를 연 뒤 약 2초 또는 READY 수신까지 기다립니다.
단, PC가 포트를 연 뒤 수신 버퍼를 비우면 READY도 지워질 수 있으므로 통신 코드에서 주의하세요.

## 6. 순서대로 시험하기

처음에는 서보 혼을 모형 문에 고정하지 않은 상태로 각도를 확인하고 장착하세요.

| 시험 | 방법 | 기대 결과 |
|---|---|---|
| 시작 | 보드 리셋 | 닫힘 방향, LED 꺼짐, CLOSED/READY |
| 거절 | DENY 입력 | 빨강 5초 후 꺼짐. 서보는 닫힘 유지 |
| 승인 대기 | WAIT → IDLE | 노랑 고정 → 꺼짐 |
| 인식 불가 | HINT → IDLE (RETRY도 허용) | 노랑 깜빡임 → 꺼짐 |
| 시간제 자동 닫힘 | OPEN을 입력하고 기다림 | 초록, OPENED 후 30초에 닫기 시작, 마지막 CLOSED |
| 반복 OPEN | OPENED 후 20초에 OPEN 한 번 더 전송 | 마지막 OPEN부터 30초에 닫기 시작 |
| 닫힘 중 새 허용 | 닫히는 중 OPEN | 현재 각도에서 다시 열고 OPENED 후 30초 유지 |
| 잘못된 명령 | HELLO 입력 | ERROR UNKNOWN_COMMAND, 상태 변화 없음 |
| PC 연결 중단 | OPEN 후 PC 프로그램 종료 | Arduino가 자체 타이머로 닫힘 처리 |
| 반복 시험 | 정상 열림·30초 유지·닫힘 50회 | 걸림·보드 리셋 없이 반복 |

마지막 두 시험도 보드와 외부 서보 전원이 유지된 조건에서 수행합니다.
USB를 뽑아 UNO 전원이 꺼지면 코드도 정지하므로 자동 닫힘을 보장하지 않습니다.
이 코드는 시연용 모형 문에만 사용합니다.

## 7. PC·DB 연결할 때 B가 처리할 일

- B의 Door 구현처럼 마지막 OPEN의 visit_id를 현재 문 주기의 방문 번호로 보관합니다.
  열린 동안 OPEN을 다시 보내면 보드의 타이머가 초기화되며 이후 CLOSED는 마지막 방문에 연결합니다.
- B의 Door.open()은 전송 성공 시 open 콜백을 보냅니다. 여기서 `save_door_event('open', visit_id)`를 호출합니다.
  OPENED까지 별도로 같은 이벤트를 중복 저장하지 않습니다. OPENED는 추가 안내 응답입니다.
- PASS 대기와 `update_passed()` 호출은 사용하지 않습니다. 통과 여부는 기록하지 않습니다.
- CLOSED 수신 시 `save_door_event('close', visit_id)`를 호출합니다.
- 시작 시 CLOSED는 연관 방문이 없으므로 visit_id 없이 기록하거나 시작 상태로만 처리합니다.
- 응답에는 방문 번호가 포함되어 있지 않습니다. 보드 리셋/포트 재연결 시 기존 방문 연결을 해제하고
  상태를 다시 맞춰야 합니다. 재전송 중복 방지용 DB event_key도 PC가 관리합니다.
- F7을 사용한다면 DB의 승인 결과를 PC가 확인해 OPEN/DENY를 보냅니다.
  WAIT 자체에는 10분 만료 타이머가 없으며 만료 처리·IDLE 복귀는 PC가 담당합니다.
- DB 상태를 바꾸는 것만으로 보드가 움직이지 않습니다. 시리얼 연결 코드는 B 담당입니다.
- B의 Door가 OPEN 전송 시 현재 visit_id를 바꾸므로 닫히는 중의 새 OPEN도 다시 열기로 적용합니다.
  시작 시 READY 이전 명령은 예외이며, 포트 재연결 때는 READY를 기다린 뒤 사용합니다.
- 기존 DB와의 호환을 위해 passed_at 컬럼과 pass 관련 함수는 그대로 두지만,
  새 하드웨어 구성에서 생성한 방문의 passed_at은 NULL로 유지합니다.
  자동 닫힘만으로 실제 통과를 추정하거나 pass 이벤트를 만들어서는 안 됩니다.
