# 방문자 확인 시스템 — C 담당 DB 구현 요약

발표자: 김동진 · 권장 구성: 슬라이드 2장, 약 2~3분

아래 슬라이드 1·2가 발표 본문입니다. 마지막 파일 설명은 발표자 참고용입니다.

## 슬라이드 1. 팀 역할과 DB 구현 내용

### 팀 역할

| 담당 | 주요 역할 |
|---|---|
| A · 정재열 | 얼굴 특징 추출·비교, 얼굴 등록 도구, 등록자/미등록자 판정 |
| B · 김성민 | 카메라·YOLO, 안내 화면·메인 루프, PC 통신, 대시보드 |
| C · 김동진 | 아두이노·모형 문·회로, DB 설계와 저장·조회 함수 |

**이번 발표 범위: C 역할 중 SQLite DB 설계와 공용 함수 구현**

### DB의 역할

**A의 얼굴 등록·인식 ↔ C의 SQLite DB ↔ B의 방문 기록·대시보드**

- 등록자 정보, 얼굴 특징 벡터, 방문 결과, 문 동작을 노트북의 DB 파일에 저장한다.
- 5개 테이블로 구성: 등록자 / 등록 얼굴 벡터 / 방문 기록 / 문 동작 / 임시 미등록 벡터.
- 사진은 별도 폴더에 보관하고 DB에는 파일 경로만 저장한다.

### 만든 주요 함수

| 기능 | 대표 함수 | 하는 일 |
|---|---|---|
| 얼굴 등록·관리 | `register_person()`, `add_embeddings()`, `load_embeddings()` | 등록자와 벡터 저장, 추가, 불러오기 |
| 방문 기록·조회 | `save_visit()`, `get_records()`, `get_today_stats()` | 판정 결과 저장, 조건 검색, 일일 통계 |
| 문 동작 기록 | `save_door_event()`, `update_passed()` | 열림·닫힘·통과 이력과 통과 시각 저장 |

> 발표 설명 예시: “저는 C 역할 중 데이터 저장 부분을 먼저 구현했습니다. A가 사용할 얼굴 등록·조회 함수와 B가 사용할 방문 기록·통계 함수를 공통으로 제공하고, 문 동작도 방문 번호에 연결해 기록하도록 만들었습니다.”

## 슬라이드 2. 오류 방지 설계와 검증 결과

### 예상한 문제와 대응

| 예상 문제 | 구현한 대응 |
|---|---|
| 잘못된 얼굴 벡터 저장·다른 모델 벡터 혼용 | 빈 벡터·유효하지 않은 숫자를 거부하고, 모델 키와 벡터 길이를 확인 |
| 저장 도중 오류가 나서 일부 데이터만 남음 | 관련 정보를 한 묶음으로 저장하고, 실패하면 함께 취소하는 트랜잭션 적용 |
| 영상 프로그램과 대시보드의 DB 동시 접근 | WAL 모드, 짧은 연결·트랜잭션, 최대 5초 잠금 대기 적용 |
| 문 신호 재처리로 중복 기록 발생 | 같은 이벤트 키의 재요청은 기존 기록을 사용하고, 최초 통과 시각 유지 |

### 추가한 데이터 관리

- 존재하지 않는 등록자·방문 번호와 잘못된 판정 상태를 검증한다.
- 미등록자 중복 확인용 벡터는 10분 뒤 조회에서 제외하고 정리 함수로 삭제한다.
- 선택 기능인 승인 처리는 이미 결정했거나 만료된 요청을 다시 승인하지 못하게 한다.
- 한국 시간 기준 날짜 조회를 지원하고, 실제 DB·사진은 Git 공유 대상에서 제외한다.

### 현재 결과와 다음 단계

- **DB 단독 검증:** 임시 DB에서 등록 → 방문 → 문 이벤트 → 조회 흐름 확인, 자동 테스트 17개 통과.
- **현재 완료:** 테이블 5개, 공용 저장·조회 함수, 설계 문서와 실행 예제.
- **다음 단계:** A/B 코드의 함수 호출·반환 형식을 맞추고, 실제 얼굴 인식 결과와 아두이노 신호로 연동 시험.

> 발표 설명 예시: “데이터가 일부만 저장되거나 같은 문 신호가 중복 기록되는 상황을 막도록 작성했습니다. DB 단독 테스트는 통과했으며, 다음에는 팀원 코드와 실제 장치를 연결해 검증할 예정입니다.”

## 발표자 참고: 만든 파일과 역할

| 파일 | 용도 |
|---|---|
| `schema.sql` | 테이블·관계·제약조건·검색용 인덱스를 정의한 설계 파일 |
| `database.py` | DB 초기화, 등록자 관리, 방문·문 기록 저장, 조회·통계 등을 제공하는 핵심 코드 |
| `tests/test_database.py` | 저장·조회, 잘못된 입력, 동시 승인, 만료 처리 등을 확인하는 17개 테스트 |
| `db_example.py` | 실제 DB를 변경하지 않고 임시 DB에서 전체 저장·조회 흐름을 보여주는 예제 |
| `DB_DESIGN.md` | 테이블 구조와 공용 함수 사용법을 정리한 팀 공유 문서 |
| `sqlite_demo.py`, `SQLITE_START.md` | SQLite의 생성·저장·조회를 익히기 위한 첫 실습 코드와 설명 |
| `.gitignore` | DB·사진·가상환경·캐시가 Git에 올라가지 않도록 제외 |
| `README.md` | 기존 팀 역할 문서에 DB 실행 방법과 설계 문서 링크 추가 |

`data/demo.db`는 기초 실습용, `data/visitor.db`는 실제 프로젝트용입니다.
두 DB 파일은 코드 실행으로 생성되며 Git에는 올리지 않습니다.

### 발표 시 구분할 내용

- “문 제어를 완성했다”가 아니라 **“문 동작을 저장하는 DB 함수를 구현했다”**고 설명한다.
- 얼굴 일치 판정과 중복 방문 판단은 A/B가 담당하고, DB는 필요한 데이터를 제공한다.
- 승인 기능은 DB 처리 함수만 준비했으며 승인 화면·실제 문 열기는 별도 연동 대상이다.
- 17개 테스트 통과는 DB 단독 검증 결과이며 실제 카메라·장치 통합 완료를 뜻하지 않는다.

### 1장으로 줄일 경우

주요 함수 표 아래에 슬라이드 2의 오류 방지 대응을 3개 정도 배치한다.
마지막에는 **“DB 단독 테스트 17개 통과, 다음 단계는 A/B·하드웨어 연동”**을 넣는다.
